Application-Level Architectures
FunctionalAPP Data transformation & purity Pure functions + data pipelines Centralized or threaded; immutable preferred Predictable logic, testability, data pipelines Elm, Clojure apps, Unix pipes, Redux reducers Grokking Simplicity (Normand)
ComponentAPP Encapsulation & composability Self-contained components with interfaces Local to each component UI systems, modular apps, plugin ecosystems React, Angular, COM, OSGi bundles Clean Architecture (Martin)
Layered / N-TierAPP Separation of concerns by layer Horizontal layers (UI → Logic → Data) Passed between layers, stored at data layer Enterprise CRUD apps, traditional web apps MVC, Spring Boot, Django, .NET MVC Patterns of Enterprise Application Architecture (Fowler)
Hexagonal (Ports & Adapters)APP Isolating domain from I/O Core domain + ports (interfaces) + adapters Inside the domain core Testable business logic, swappable infrastructure DDD services, Clean Architecture implementations Architecture Patterns with Python (Percival & Gregory)
Event-DrivenAPP Loose coupling via async events Producers, consumers, event channels Event log / event store; state derived from events Reactive systems, real-time processing Kafka pipelines, Node.js EventEmitter, CQRS/ES Designing Event-Driven Systems (Stopford)
Pipeline / Pipes & FiltersAPP Sequential data processing Filters connected by pipes Stateless filters; data flows through ETL, compilers, stream processing Unix shell pipelines, Apache Beam, compiler passes Fundamentals of Software Architecture (Richards & Ford)
System / Infrastructure Architectures
InfrastructureSYS Hardware, networking, deployment Servers, networks, load balancers, cloud regions Distributed across nodes; managed by orchestrators Scalability, reliability, deployment topology AWS VPC diagrams, Kubernetes clusters, Terraform configs Designing Data-Intensive Applications (Kleppmann)
MicroservicesSYS Independent deployability Small, autonomous services Each service owns its database Large teams, independent scaling, polyglot stacks Netflix, Spotify squads, Amazon service teams Building Microservices (Newman)
Service-Oriented (SOA)SYS Reusable enterprise services Coarse-grained services + ESB Shared databases common; distributed transactions Enterprise integration, legacy modernization SOAP services, ESB middleware, WS-* standards Enterprise Integration Patterns (Hohpe & Woolf)
Behavioral Architecture
State Machine / StatechartBEH Explicit states & transitions States, events, transitions, guards Current state is the primary concern; transitions are explicit Workflows, UI flows, protocols, embedded systems XState, UML statecharts, TCP protocol, traffic lights Constructing the User Interface with Statecharts (Horrocks)
Data-Centric Architectures
Data ArchitectureDATA Data models, flow, storage, governance Schemas, lakes, warehouses, pipelines Central concern — data at rest and in motion Analytics, compliance, data-heavy orgs Star schemas, data lakes, dbt models, data mesh Designing Data-Intensive Applications (Kleppmann)
Organizational / Strategic Architectures
Enterprise ArchitectureORG Aligning IT with business strategy Business capabilities, application portfolio Not a primary concern — focuses on governance Large organizations, IT strategy, roadmaps TOGAF, Zachman Framework, ArchiMate models Enterprise Architecture as Strategy (Ross, Weill, Robertson)
Technical ArchitectureORG Technology choices & standards Tech stack, protocols, frameworks, patterns Defines how state is managed across the stack Platform decisions, tech standardization ADRs, tech radar, reference architectures Technology Strategy Patterns (Hewitt)
Security ArchitectureORG Threat modeling & access control Trust boundaries, auth flows, encryption zones Session state, token lifecycle, audit logs Compliance, secure systems, zero-trust design OAuth2 flows, RBAC models, STRIDE threat models Designing Secure Software (Deogun et al.)
Key insight: These are not mutually exclusive choices. A real system typically combines several — for instance, a microservices system (system-level) where each service uses hexagonal architecture (application-level), state machines for workflow logic (behavioral), all deployed on a well-defined infrastructure architecture, governed by an enterprise architecture framework.

If you only read two books: Fundamentals of Software Architecture (Richards & Ford) for the broadest survey of application and system styles, and Designing Data-Intensive Applications (Kleppmann) for infrastructure, data, and distributed systems.
