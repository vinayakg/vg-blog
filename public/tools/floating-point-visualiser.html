How It Works

IEEE 754 Floating-Point Format

Floating-point numbers are stored using three components:

Component Single (32-bit) Double (64-bit) Purpose
Sign 1 bit 1 bit 0 = positive, 1 = negative
Exponent 8 bits 11 bits Determines the scale/magnitude
Mantissa (Fraction) 23 bits 52 bits Stores the precision/significant digits

The Formula

The actual value is calculated as:

value = (-1)^sign × 1.mantissa × 2^(exponent - bias)

Where:

  • Bias = 127 for single precision, 1023 for double precision
  • 1.mantissa = implicit leading 1 + fractional part from mantissa bits

Special Values

  • Zero: exponent = 0, mantissa = 0
  • Infinity: exponent = all 1s, mantissa = 0
  • NaN (Not a Number): exponent = all 1s, mantissa ≠ 0
  • Subnormal: exponent = 0, mantissa ≠ 0 (very small numbers)

Converting Fractions to Binary

Converting the fractional part of a decimal number to binary uses a different algorithm than converting integers:

Algorithm: Multiply by 2 repeatedly

1. Take the fractional part
2. Multiply by 2
3. If result ≥ 1: record "1" and subtract 1
4. If result < 1: record "0"
5. Repeat with the new fractional part

Example: Convert 0.625 to binary

Fraction × 2 Result Bit New Fraction
0.625 × 2 1.25 1 0.25 (subtract 1)
0.25 × 2 0.5 0 0.5
0.5 × 2 1.0 1 0.0 (done!)

Reading top to bottom: 0.625₁₀ = 0.101₂

Why some fractions can't be exactly represented:

Just like 1/3 = 0.333... in decimal (repeating forever), many decimal fractions become repeating patterns in binary. For example, 0.1₁₀ = 0.0001100110011...₂ (repeating). This is why 0.1 + 0.2 ≠ 0.3 in many programming languages!
